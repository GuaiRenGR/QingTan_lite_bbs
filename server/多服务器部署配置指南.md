# 多服务器部署配置指南

## 概述

轻坛支持多服务器部署架构：多台服务器各自拥有独立的 MySQL 数据库，通过**操作日志同步**机制保持数据最终一致。文件存储统一使用 OneDrive 作为后端，无需同步。

### 架构要点

- **独立数据库**：每台服务器运行自己的 MySQL 实例，表结构相同但数据独立写
- **auto_increment 偏移**：通过 `auto_increment_increment = 总数` + `auto_increment_offset = server_id` 避免主键冲突
- **操作日志同步**：写操作写入 `sync_operation_log` 表，由 Web 定时器 + 请求采样触发推拉同步
- **客户端故障转移**：Flutter App 内置 ServerManager，自动检测服务器健康状态并在 15 秒内切换
- **写队列**：离线时写请求暂存本地，恢复后自动重放

---

## 前置要求

- PHP >= 7.4，PDO MySQL 扩展
- MySQL/MariaDB >= 5.7
- 每台服务器独立域名或子域名
- 所有服务器共用同一 OneDrive 配置（`config/onedrive.php`）

---

## 第一步：运行升级脚本

在 **每台服务器** 上顺序执行：

1. 确保 `config/database.php` 已正确配置（数据库连接信息）
2. 将 `upgrade_multi_server.php` 上传到服务器根目录
3. 通过浏览器访问 `http://你的域名/upgrade_multi_server.php`
4. 确认所有输出显示 ✓ 绿色通过

脚本会：
- 创建 `sync_operation_log`、`sync_server_status`、`id_sequences` 三张表
- 自动初始化主表（threads/posts/users/forums 等）的 ID 序列
- 生成 `config/servers.php` 默认配置
- 记录版本号到 `app_versions` 表

**安全：升级完成后立即删除 `upgrade_multi_server.php`！**

## 第二步：配置 config/servers.php

每台服务器独立修改 `config/servers.php`，关键项：

```php
'server_id'   => 1,          // 本机在集群中的 ID，必须唯一且 >= 1
'server_name' => '主服务器',  // 本机显示名称
'server_url'  => 'http://newbbs.hj1bbs.top',  // 本机完整 URL，供其他服务器和客户端访问
```

### servers 列表（所有服务器信息）

```php
'servers' => [
    ['id' => 1, 'name' => '主服务器',   'url' => 'http://newbbs.hj1bbs.top', 'weight' => 10],
    ['id' => 2, 'name' => '备用服务器', 'url' => 'http://s2.example.com',    'weight' => 5],
    ['id' => 3, 'name' => '备用服务器', 'url' => 'http://s3.example.com',    'weight' => 5],
],
```

- `id`：服务器唯一标识，必须与 `server_id` 对应
- `url`：服务器完整 URL，用于同步通信和客户端连接
- `weight`：客户端负载权重，越高分配越多的请求。主服务器设为 10，备机设为 5

> 所有服务器的 `servers` 列表必须一致（内容相同），同步才能正常发现对端。

### sync 配置

```php
'sync' => [
    'sync_token'  => 'change-this-to-a-secure-random-token',
    'batch_size'  => 100,
    'retry_times' => 3,
    'timeout'     => 30,
    'sample_rate' => 10,
],
```

| 参数 | 说明 | 建议值 |
|------|------|--------|
| `sync_token` | 服务器间同步的鉴权令牌，每台服务器必须一致 | 随机 32 位十六进制 |
| `batch_size` | 每次同步拉取的最大操作日志条数 | 100~500 |
| `retry_times` | 同步失败时的重试次数 | 3 |
| `timeout` | 同步 HTTP 请求超时（秒） | 30 |
| `sample_rate` | 普通请求触发同步的概率百分比（0 为关闭） | 10（即 10% 请求触发） |

### 示例：三服务器部署

**服务器 A（主，ID=1）** `config/servers.php`：
```php
'server_id' => 1,
'server_url' => 'https://bbs1.example.com',
'servers' => [
    ['id' => 1, 'name' => '香港节点', 'url' => 'https://bbs1.example.com', 'weight' => 10],
    ['id' => 2, 'name' => '东京节点', 'url' => 'https://bbs2.example.com', 'weight' => 5],
    ['id' => 3, 'name' => '新加坡节点', 'url' => 'https://bbs3.example.com', 'weight' => 5],
],
'sync' => [
    'sync_token' => 'a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6',
    // ...
],
```

**服务器 B（备，ID=2）** `config/servers.php`：
```php
'server_id' => 2,
'server_url' => 'https://bbs2.example.com',
// servers 列表和 sync_token 与服务器 A 完全一致
```

**服务器 C（备，ID=3）** `config/servers.php`：
```php
'server_id' => 3,
'server_url' => 'https://bbs3.example.com',
// servers 列表和 sync_token 与服务器 A 完全一致
```

> 重要：`servers` 列表和 `sync_token` 在所有服务器上必须完全一致！只有 `server_id` 和 `server_url` 按实际身份修改。

## 第三步：客户端配置

### 修改 app_config.dart

编辑 `hjyz_bbs/lib/core/config/app_config.dart`，配置所有服务器：

```dart
static const String apiEntry = 'http://newbbs.hj1bbs.top/index.php?route=';
static const String wsEntry = 'ws://newbbs.hj1bbs.top:9501';

static const List<ServerConfig> serverList = [
  ServerConfig(id: 1, name: '主服务器',   url: 'http://newbbs.hj1bbs.top',  weight: 10),
  ServerConfig(id: 2, name: '备用服务器', url: 'http://s2.example.com',     weight: 5),
  ServerConfig(id: 3, name: '备用服务器', url: 'http://s3.example.com',     weight: 5),
];
```

- `apiEntry` 和 `wsEntry` 仍用作回退地址（仅当所有服务器不可用时使用）
- `serverList` 用于客户端的健康检查、故障转移和负载分担
- weight 越高的服务器被选中的概率越大

### 构建发布

```bash
flutter build apk --release
```

分发安装包即可，客户端会自动探测服务器状态并切换。

## 同步机制说明

### 同步流程

```
服务器 A（写入）         服务器 B（读取）
      │                       │
      │── 写操作 ──→ 记录到    │
      │    sync_operation_log  │
      │                       │
      │── Web 定时器触发 ──→   │
      │    POST /syncPush      │
      │    （本机新日志）       │
      │←── 收到并应用 ──────── │
      │                       │
      │←── Web 定时器触发 ──── │
      │    POST /syncPull      │
      │    （拉取对端新日志）   │
      │── 收到并应用 ──────→   │
```

### 触发方式

1. **Web 定时器**（推荐）：在任意一台服务器的 crontab 中设置：
   ```
   * * * * * curl -s "http://你的域名/index.php?route=sync/syncTrigger&token=你的sync_token" >/dev/null 2>&1
   ```
   如果无法使用 crontab，可使用第三方定时任务服务（如 cron-job.org）每 30~60 秒访问此 URL。

2. **请求采样自动触发**：普通用户请求有 `sample_rate%` 的概率触发一次同步。例如 sample_rate=10 表示每 10 次用户请求有 1 次额外执行同步。生产环境建议 5~10。

3. **健康检查**：服务器之间通过 `/index.php?route=system/ping` 相互检测在线状态，同步会自动跳过离线服务器。

### 冲突处理

- 采用 **last-write-wins** 策略
- 每条操作日志由 `(server_id, src_op_id)` 唯一标识，重复日志自动跳过（INSERT IGNORE）
- 先同步 INSERT（创建行），再同步 UPDATE/DELETE（操作已有行）
- 如果某行不存在（如跨服务器先删除后插入），DELETE 操作被忽略，不报错

## 日常运维

### 查看同步状态

```
GET /index.php?route=sync/syncStatus&token=你的sync_token
```

返回示例：
```json
{
  "code": 0,
  "data": {
    "server_id": 1,
    "server_name": "主服务器",
    "unpushed_count": 12,
    "last_sync_at": "2026-07-01 10:30:00",
    "peers": [
      { "server_id": 2, "status": "active", "last_sync_at": "2026-07-01 10:30:05" },
      { "server_id": 3, "status": "active", "last_sync_at": "2026-07-01 10:29:50" }
    ]
  }
}
```

### 健康检查

```
GET /index.php?route=system/ping
```

返回：
```json
{ "code": 0, "message": "pong", "data": { "server_id": 1, "server_name": "主服务器", "time": "2026-07-01 10:00:00" } }
```

### 强制全量同步

```
GET /index.php?route=sync/syncTrigger&token=你的sync_token&full=1
```

`full=1` 表示忽略 `last_sync_op_id`，从最早的未同步日志开始推送。

### 检查某台服务器是否存活

在所有服务器的 `sync_server_status` 表中，`status` 列标记：
- `active` — 正常工作
- `inactive` — 连续 3 次 ping 无响应后自动标记

也可在 Flutter 客户端日志中查看各服务器的 `ServerHealth` 状态。

## 单服务器模式

如果不需要多服务器，保持单服务器模式即可（无需修改任何配置）：

- `config/servers.php` 可删除或留空；服务端检测不到 `servers` 配置会自动跳过同步逻辑
- 客户端 `serverList` 只保留一个条目即可：
  ```dart
  static const List<ServerConfig> serverList = [
    ServerConfig(id: 1, name: '主服务器', url: 'http://yourdomain.com', weight: 10),
  ];
  ```

## 常见问题

### Q: sync_token 泄露了怎么办？

立即修改所有服务器 `config/servers.php` 中的 `sync_token`，然后重启 Web 服务器。旧 token 立即失效。

### Q: 两台服务器同时写入同一条记录？

因为独立数据库，不会同时写同一条物理记录（主键 ID 不同）。冲突仅在同步阶段出现（例如 A 更新了某帖子标题，B 也更新了同帖子的标题）。此时 last-write-wins：后同步过来的值覆盖当前值。

### Q: 同步延迟多久？

取决于 cron 触发频率。如果每 30 秒触发一次，延迟 < 30 秒。请求采样同步可将延迟降至秒级。

### Q: 某台服务器完全损坏，数据丢失怎么办？

使用健康状态正常的服务器作为主库，让所有客户端切换到可用的服务器。丢失的数据可通过其他服务器的 `sync_operation_log` 重放恢复。建议定期用 `mysqldump` 备份数据库。

### Q: 我可以混合使用不同的 PHP 版本吗？

可以，只要都 >= 7.4。但建议所有服务器使用相同的 PHP 版本和小版本，避免函数行为差异。

### Q: 新增了一台服务器，如何加入集群？

1. 在新服务器上安装轻坛（运行 `install.php`）
2. 复制任意现有服务器的 `config/servers.php`，修改 `server_id` 和 `server_url` 指向自身
3. 修改所有现有服务器的 `servers` 列表，加入新服务器条目
4. 重新发布 Flutter 客户端（更新 `serverList`）
5. 新服务器会通过同步机制从其他服务器拉取历史数据
